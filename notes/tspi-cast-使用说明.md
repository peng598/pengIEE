# TSPI Cast 使用说明

TSPI Cast 用于把 Android 手机画面通过手机热点投到立创泰山派 RK3566 的 HDMI 显示器。

## 已完成

- 手机端系统录屏授权
- H.264 硬件编码，最高长边 1280 像素、30 FPS
- 手机热点局域网传输
- 自动发现泰山派接收端
- 手动输入板卡 IP 作为备用方式
- 泰山派 H.264 硬件解码和全屏显示
- 断线后自动回到等待状态

## 使用步骤

1. 在 Android 手机上安装 `TSPI-Cast-Sender-Android.apk`。
2. 打开手机热点。
3. 泰山派接收端已安装并运行；点击屏幕上的 `WI-FI SETTINGS`，连接手机热点。
4. 接收端会显示泰山派在热点中的 IP 地址。
5. 打开手机上的 `TSPI Cast Sender`，点击 `FIND RECEIVER`。
6. 如果自动发现失败，在输入框中填写接收端显示的 IP 地址。
7. 点击 `START CASTING`，在 Android 系统弹窗中允许录制屏幕。
8. 点击手机 App 中的 `STOP`，或通过通知栏停止投屏。

## 网络端口

- `53516/TCP`：H.264 视频流
- `53517/UDP`：接收端自动发现

所有数据只在手机热点局域网内传输，不需要互联网。

## 第一版限制

- 只支持 Android 手机发送端。
- 当前只传输画面，不传输声音。
- 手机旋转屏幕后，建议停止并重新开始投屏。
- 当前没有连接密码，仅建议在个人热点中使用。

## 视频链路的延迟与吞吐预算

端到端延迟由捕获等待、编码、发送排队、网络、解码和显示同步构成：

$$T_\mathrm{end}=T_\mathrm{capture}+T_\mathrm{encode}+T_\mathrm{queue}
+T_\mathrm{network}+T_\mathrm{decode}+T_\mathrm{display}$$

30 FPS 对应帧周期约 $33.3\,ms$。仅发送队列多积压 6 帧，就会额外引入约 $200\,ms$ 延迟；带宽正常但画面明显落后时，应先检查队列长度和 TCP 队头阻塞，不能只提高码率。若编码平均码率为 $4\,Mbit/s$，平均负载约 $0.5\,MB/s$；I 帧突发、Wi-Fi 重传与热点竞争仍要求吞吐裕量，此数值是估算示例，不代表当前 APK 的固定配置。

## 逐层故障定位

| 现象 | 核对项 | 能区分什么问题 |
|---|---|---|
| 自动发现失败，手动 IP 可用 | UDP 53517、广播/组播范围、热点隔离 | 发现协议与视频链路分别定位 |
| TCP 已连接但黑屏 | SPS/PPS 是否到达、NAL 边界、首个可解码 IDR | 建链成功不等于码流可解码 |
| 起初流畅，随后越来越慢 | 发送/接收队列长度、丢帧策略、热降频 | 持续吞吐不足与瞬时抖动 |
| 旋转后花屏或无画面 | 分辨率、编码参数、解码器重建和显示尺寸 | 参数集变化未完整处理 |
| 断线重连后仍显示旧帧 | 连接世代标识、缓存清空、IDR 请求 | 旧会话数据与新会话混用 |

TCP 是字节流，不保留一次 write 对应一次 read 的边界。接收端必须根据明确的长度字段或合法 NAL 分隔规则重组，不能假设每次读取恰好一帧。重新连接后应等待当前会话的参数集与随机访问帧，避免把任意 P 帧交给尚无参考图像的解码器。

## 建议的体验验收

用同一个递增时间码画面同时拍摄手机与 HDMI 屏，比较相同帧的显示时刻；报告中位值和最差值，并注明是否包含显示器延迟。再分别测试近距离、遮挡、热点负载、10 分钟运行温升及锁屏/解锁。记录编码码率、帧率、解码丢帧、重连耗时与队列上限。当前版本没有身份验证，发现到设备名也不等于已验证发送端身份；产品化时需另行设计配对与会话权限。
