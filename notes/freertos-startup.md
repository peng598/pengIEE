# 系统启动流程及任务相关函数

vTaskStartScheduler 启动调度器；正常运行时不返回。启动所需内存分配失败、端口启动失败等路径可能返回，因此后续必须进入明确的故障处理。停止 API 名称是 vTaskEndScheduler，但常用 Cortex-M MCU 端口通常不支持结束调度器并恢复到裸机执行，不能把它当作普通停机机制。

## 首任务启动之前必须满足的条件

1. 系统时钟、向量表位置和运行库初始化完成；主栈位于可写 RAM 且对齐满足 ABI。
2. 业务任务和通信对象创建成功，检查返回值与句柄；不要让 ISR 访问尚未创建的队列或通知句柄。
3. Idle 任务可创建；启用软件定时器时，Timer Service 任务及命令队列也需要内存。静态分配配置要提供相应应用回调。
4. SVC、PendSV、SysTick 正确链接到对应端口；若使用替代 tick 源，按端口方案配置，避免 HAL 与内核重复处理同一中断。
5. FPU 硬件、编译 ABI 与 CM4F 端口相容；从引导程序跳转时还须清理遗留中断、SysTick 和栈选择。

## 上下文恢复原理

创建任务时，内核把任务入口、参数、初始 xPSR 等组织成一个“仿异常栈帧”。在 ARM_CM4F 端口，SVC 恢复首任务所需寄存器和 PSP，再通过异常返回进入线程模式。之后 PendSV 负责切换上下文；因此能进入 main 但进不了任务，往往涉及端口、栈帧或异常向量，而非任务函数本身。

| 故障现象 | 首先保存的证据 | 排查方向 |
|---|---|---|
| 调度器调用后立即返回 | 创建任务结果、剩余堆、最小历史堆 | Idle/Timer 任务分配、动态/静态配置 |
| 卡在 SVC/Default_Handler | VTOR、SVC 向量、链接 MAP | 弱符号未覆盖、重名处理函数 |
| 首任务直接 HardFault | EXC_RETURN、PSP、堆栈 PC、CFSR | 栈不足、地址非法、FPU/ABI 不匹配 |
| 任务开始后不再唤醒 | SysTick 装载值、屏蔽寄存器、tick 计数 | 时钟错误、重复初始化或中断长期被屏蔽 |

## 启动内存核算

若 StackType_t 为 4 字节，控制任务 768 words、通信任务 384 words、服务任务 256 words、Idle 128 words，单是任务栈便需要 $(768+384+256+128)\times4=6144$ 字节。还要加入 TCB、队列存储、块头与对齐开销；启用定时器后继续累加，不能只把总 RAM 减去局部变量估算可用堆。

建议在调度器前生成一次启动诊断快照：固件版本、时钟、创建结果、每任务栈深度和关键向量。首任务启动后再记录实测 tick 周期；生产停机流程则由应用状态机关闭输出、停止新请求并等待资源释放，不依赖结束内核。
